# TRA-001 — Master Trade : le domaine de l'Offre

Construit le premier processus métier de NAFA sur les trois référentiels
existants. **Domaine seul** — schéma, service et adaptateurs viennent en
TRA-002 (précédents GEO-002, PROD-002).

Base : `origin/main`. ADR : 0011 (la révision de l'axe scope promise par
ADR-0009 §8).

## TRA-001.2 — L'agrégat `Offer`

**Périmètre**

- VOs : `OfferId`, `Quantity` (positif, fini), `Money` (amountMinor entier
  > 0, currency ISO 4217), `OfferWindow` (from, to nullable ≥ from),
  > `OfferStatus` + machine de transitions
- `TradeRule` + `TradeRuleViolation`
- Événements : `offer.registered/.published/.withdrawn/.closed/.price-revised`
- L'agrégat : register / rehydrate / snapshot / pullEvents, version
  absolue + expectedVersion ; mutations `publish`, `withdraw`, `close`,
  `revisePrice`
- Factory `createOffer` : valide les VOs, interroge `SellerRegistry` et
  `ProductCatalog`, puis délègue à `register`

**Invariants numérotés (1-10)**

1. `OfferId` est un UUID valide
2. Le vendeur existe et est actif — **question de collection** (port)
3. Le produit existe et est PUBLISHED — **question de collection** (port)
4. La quantité est strictement positive et finie
5. L'unité est déclarée par le produit — **question de collection** (port)
6. Le prix unitaire est valide (amountMinor entier > 0, currency `[A-Z]{3}`)
7. La fenêtre est cohérente (to null ou ≥ from)
8. Les transitions de statut sont valides — `DRAFT → PUBLISHED →
WITHDRAWN | CLOSED`, `DRAFT → WITHDRAWN`, jamais de retour
9. L'identité est immuable : vendeur, produit, unité, quantité, zone ne
   changent jamais après enregistrement
10. `WITHDRAWN` et `CLOSED` figent tout

**Critères d'acceptation** — chaque invariant a son test ; les événements
portent le préfixe `offer.` ; `revisePrice` autorisé seulement sous
PUBLISHED et tracé.

## TRA-001.3 — Ports

**Périmètre**

- `OfferRepository` — `findById`, `findBySeller`, `findByProduct`,
  `findByPickupArea`, `save(offer, expectedVersion)`
- `ProductCatalog` — `getPublishedProduct(productId) → { units } | null`
  (l'existence du produit publié et ses unités déclarées)
- `SellerRegistry` — `isActive(actorId)` (v1 : booléen)
- Jetons `Symbol` + contract spec avec doubles

**Critères d'acceptation** — `save(aggregate, expectedVersion)`, signature
identique ACTOR/GEO/PROD ; aucun `class ... implements` hors des doubles
de test.
